## 1. Edit Mind 用户案例

### 1.1 创始人使用场景
**来源**：GitHub README、项目文档

**背景**：
- 创始人因 Google Cloud Platform Video Intelligence API 费用过高（$450）而开发
- 需求：本地化、隐私保护、成本可控的视频搜索方案

**部署规模**：
- 个人/小团队使用
- 视频数量：数百到数千个
- 硬件：支持 CPU 和 GPU 模式

**技术选型原因**：
- 完全本地化，无需上传到云端
- 支持多种 AI 模型（Whisper、YOLO、DeepFace）
- 开源免费，可自定义扩展

**实际效果**：
- 成本节省：避免云 API 费用
- 隐私保护：数据不离开本地
- 功能完整：转录、物体检测、人脸识别、语义搜索

### 1.2 社区反馈
**来源**：GitHub Issues、Discussions

**积极反馈**：
- 功能强大，支持多模态搜索
- Docker 部署简单

**常见问题**：
- 端口冲突（PostgreSQL 5432、Redis 6379）
- 环境变量配置复杂（SESSION_SECRET、ENCRYPTION_KEY）
- GPU 配置需要 NVIDIA Container Toolkit

## 2. Immich 用户案例

### 2.1 大规模部署案例
**来源**：Reddit r/selfhosted、GitHub Discussions

**典型用户**：
- 家庭用户：10,000-50,000 张照片/视频
- 摄影师：100,000+ 张照片
- 小型工作室：多用户共享

**硬件配置**：
- CPU：4-8 核
- 内存：8-16 GB
- 存储：1-10 TB
- GPU：可选（加速机器学习）

**部署方式**：
- Docker Compose（最常见）
- Kubernetes（大规模部署）
- Unraid、TrueNAS（NAS 用户）

**实际性能**：
- 照片上传：10-50 张/秒
- 人脸识别：1,000 张照片约 10-30 分钟（GPU）
- 搜索响应：<1 秒（10,000 张照片）

### 2.2 常见问题与解决方案

**问题 1：机器学习任务占用资源过高**
- 症状：CPU/内存占用 100%，系统卡顿
- 解决方案：
  - 限制并发任务数
  - 使用 GPU 加速
  - 调整任务优先级

**问题 2：数据库性能下降**
- 症状：搜索变慢，页面加载缓慢
- 解决方案：
  - 定期清理数据库
  - 优化索引
  - 升级 PostgreSQL 版本

**问题 3：存储空间不足**
- 症状：上传失败，缩略图生成失败
- 解决方案：
  - 定期清理缩略图
  - 使用外部存储（S3、MinIO）
  - 压缩原始照片

## 5. 部署最佳实践

### 5.1 硬件选型

**CPU 密集型任务**：
- 视频解码
- 数据库查询
- 任务调度
- 推荐：8+ 核心

**GPU 加速任务**：
- 语音转录（Whisper）
- 物体检测（YOLO）
- 人脸识别（DeepFace）
- 向量生成（Embedding）
- 推荐：NVIDIA RTX 3060+ 或 A4000+

**内存需求**：
- 基础运行：8 GB
- 推荐配置：16-32 GB
- 大规模部署：64+ GB

**存储规划**：
- 原始视频：按实际需求
- 数据库：10-50 GB
- 向量数据库：5-20 GB
- 缩略图/预览：视频数量 × 1-5 MB
- 模型缓存：10-20 GB

### 5.2 网络配置

**端口规划**：
- Web 前端：3000-4000 范围
- API 服务：4000-5000 范围
- 数据库：5432（PostgreSQL）、6379（Redis）
- 向量数据库：8000（ChromaDB）
- ML 服务：8765

**反向代理**：
- Nginx、Traefik、Caddy
- HTTPS 证书（Let's Encrypt）
- 域名配置

**防火墙规则**：
- 仅开放必要端口
- 限制外部访问
- VPN 访问（远程使用）

### 5.3 性能优化

**并发配置**：
- 从保守值开始（1-2）
- 逐步提升（2-4-6）
- 监控资源占用
- 避免过度并发

**缓存策略**：
- Redis 缓存热点数据
- CDN 缓存静态资源
- 浏览器缓存配置

**数据库优化**：
- 定期 VACUUM
- 索引优化
- 连接池配置
- 查询优化

### 5.4 监控与维护

**关键指标**：
- CPU/GPU 使用率
- 内存占用
- 磁盘 I/O
- 网络带宽
- 任务队列长度
- 数据库连接数

**监控工具**：
- Prometheus + Grafana
- Docker stats
- nvidia-smi（GPU）
- PostgreSQL 慢查询日志

**定期维护**：
- 数据库备份（每日）
- 日志清理（每周）
- 系统更新（每月）
- 性能审计（每季度）

## 6. 常见问题与解决方案

### 6.1 安装部署问题

**问题：端口冲突**
- 检查：`sudo lsof -i :端口号`
- 解决：修改 docker-compose.yml 端口映射
- 或：停止占用端口的服务

**问题：GPU 不可用**
- 检查：`nvidia-smi`、`docker info | grep -i runtime`
- 解决：安装 NVIDIA Container Toolkit
- 验证：`docker run --rm --gpus all nvidia/cuda:12.8.0-base-ubuntu22.04 nvidia-smi`

**问题：Ollama 无法连接**
- 检查：Ollama 监听地址（0.0.0.0:11434）
- 解决：macOS/Windows 通常可用 `host.docker.internal`；Linux 需要填写容器真实可达的宿主机 IP，或先配置 `host-gateway`
- 验证：
  - macOS/Windows：`curl http://host.docker.internal:11434/api/tags`
  - Linux：`curl http://<your-host-ip>:11434/api/tags`

### 6.2 性能问题

**问题：视频处理缓慢**
- 检查：GPU 是否启用
- 检查：并发配置是否过低
- 检查：磁盘 I/O 是否瓶颈
- 解决：启用 GPU、提高并发、使用 SSD

**问题：搜索响应慢**
- 检查：向量数据库大小
- 检查：数据库索引
- 检查：Redis 缓存命中率
- 解决：优化索引、增加缓存、升级硬件

**问题：内存不足**
- 检查：并发任务数
- 检查：模型加载策略
- 解决：降低并发、增加内存、优化模型

### 6.3 数据管理问题

**问题：存储空间不足**
- 检查：`df -h`、`docker system df`
- 解决：清理 Docker 镜像/容器、删除旧数据、扩展存储

**问题：数据库膨胀**
- 检查：PostgreSQL 数据库大小
- 解决：定期 VACUUM、清理旧记录、归档历史数据

**问题：向量数据库性能下降**
- 检查：ChromaDB 集合大小
- 解决：分片存储、定期重建索引；如果未来单独实施替代向量库，再评估 Qdrant / Milvus

## 7. 成功案例总结

### 7.1 个人用户
- **规模**：100-1,000 个视频
- **硬件**：8 核 CPU + RTX 3060
- **成本**：硬件投入 $1,000-2,000，无持续费用
- **效果**：完全满足需求，搜索体验优秀

### 7.2 小型团队
- **规模**：1,000-10,000 个视频
- **硬件**：16 核 CPU + RTX 3090 或 A4000
- **成本**：硬件投入 $3,000-5,000，无持续费用
- **效果**：性能稳定，成本远低于云 API

### 7.3 中型企业
- **规模**：10,000-100,000 个视频
- **硬件**：32+ 核 CPU + 多 GPU 或专用服务器
- **成本**：硬件投入 $10,000-50,000，无持续费用
- **效果**：需要专业运维，但长期成本优势明显

## 8. 关键经验总结

### 8.1 技术选型
- 小规模（<1,000 视频）：Edit Mind、Immich
- 中规模（1,000-10,000 视频）：Edit Mind + 性能优化
- 大规模（>10,000 视频）：考虑 Qdrant/Milvus 替代 ChromaDB

### 8.2 硬件投入
- 最小配置：8 核 CPU + 16 GB 内存
- 推荐配置：16 核 CPU + 32 GB 内存 + RTX 3060+
- 高性能配置：32+ 核 CPU + 64+ GB 内存 + RTX 3090/A4000+

### 8.3 运维要点
- 从小规模开始，逐步扩展
- 持续监控性能指标
- 定期备份数据
- 保持系统更新

### 8.4 成本效益
- 云 API：按使用量计费，长期成本高
- 自托管：初期投入高，长期成本低
- 临界点：约 1,000 小时视频（云 API $6,000 vs 自托管 $3,000-5,000）

## 10. 结论

**关键发现**：
- 自托管视频搜索方案在技术上完全可行
- 硬件投入合理，长期成本优势明显
- 社区活跃，问题解决方案丰富
- 适合隐私敏感、大规模使用场景

**最佳实践**：
- 从小规模开始，逐步扩展
- 重视硬件选型，特别是 GPU
- 持续监控和优化
- 定期备份和维护

**风险提示**：
- 需要一定的技术能力
- 初期配置较复杂
- 需要持续运维投入
- 大规模部署需要专业支持
