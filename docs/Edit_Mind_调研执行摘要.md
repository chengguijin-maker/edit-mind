## 三、性能基准与优化

### 3.1 转录性能（您的硬件配置）

**基准数据** (单个RTX 3090):

| 模型 | 公开 benchmark 参考区间 | 当前仓库口径 | 显存占用 |
|------|-----------------------|--------------|---------|
| medium | 数倍实时 | 默认模型 | 4-6GB |
| large-v3 | 通常更慢但更准 | 非默认，需要单独评估 | 8-10GB |

**并发建议** (3×RTX 3090):

| 阶段 | 建议值 | 说明 |
|------|--------|------|
| 起步 | `1 / 1` | 先确认完整链路稳定 |
| 观测后 | `2 / 2` | 观察 GPU、CPU、Redis、PostgreSQL、Chroma |
| 压测后 | `4 / 4` | 仅在排队和稳定性都可接受时继续提升 |

**推荐配置**:
```env
MAX_CONCURRENT_TRANSCRIPTIONS="1"
MAX_CONCURRENT_ANALYSES="1"
```

补充说明：

- 当前仓库没有 `WHISPER_MODEL` 这个 `.env` 开关。
- 如果要切换到更大 Whisper 模型，需要修改 Python 服务启动参数，而不是只改环境文件。

### 3.2 视觉分析性能

这里更适合把 YOLO / DeepFace 数字理解为公开 benchmark 或外部经验区间，而不是当前仓库的端到端承诺。

当前仓库真正需要结合代码一起理解的是：

- 默认采样间隔已经是 `5 秒`
- 单个采样帧会顺序执行多个插件
- `audio / visual embedding` 默认 worker 并发已是 `2`
- 因此不能只按单个 YOLO FPS 或单个人脸模型时间外推完整索引耗时

### 3.3 端到端性能预估

当前仓库没有附带这套工作区可复验的统一端到端 benchmark 输出，
所以这里不再把具体分钟数写成“当前版本承诺”。

更稳妥的做法是：

1. 先对 10-20 个真实视频建立基线
2. 记录转录、帧分析、scene、embedding 各阶段耗时
3. 在并发 `1 / 2 / 4` 下重复压测
4. 再根据真实结果外推 100 个视频级别的计划窗口

## 四、部署与优化路线图

### 4.1 第一阶段：安装部署 (第1周)

**目标**: 成功运行系统，完成小规模测试

**关键任务**:
1. 解决端口冲突（推荐方案B：docker-compose.override.yml）
2. 配置环境变量（SESSION_SECRET、ENCRYPTION_KEY、HOST_MEDIA_PATH）
3. 选择AI提供方（推荐Gemini或本地Ollama）
4. 验证GPU可用性（nvidia-smi、docker GPU运行时）
5. 小规模测试（10-50个视频）

**验收标准**:
- [ ] 所有容器正常启动
- [ ] Web界面可访问
- [ ] 成功处理至少10个测试视频
- [ ] 搜索功能正常工作

### 4.2 第二阶段：性能调优 (第2-4周)

**目标**: 优化配置，提升处理效率

**关键任务**:
1. 逐步提高并发数（1→2→4）
2. 监控资源使用（CPU、GPU、内存、磁盘）
3. 如确有需要，再通过 Python 服务参数评估更大的采样间隔
4. 测试不同Whisper模型（medium vs large-v3）
5. 中规模测试（100-500个视频）

**性能指标**:
- 单视频处理时间持续下降并保持稳定完成
- GPU利用率保持在健康区间，避免长时间空转或打满
- 内存使用 < 200GB
- 磁盘I/O无瓶颈

### 4.3 第三阶段：扩展升级 (第2个月)

**目标**: 判断是否真的需要替换当前向量存储

**关键任务**:
1. 评估视频数量增长趋势
2. 确认真实瓶颈是否已经来自 Chroma 而不是 scene / plugin / embedding
3. 优化数据库查询性能
4. 实施数据备份策略
5. 监控系统稳定性

**说明**:
- 当前仓库默认实现仍是 ChromaDB
- 如果未来确实需要替代向量库，应单独立项设计迁移方案，而不是直接把外部示例配置当成当前仓库内置能力

### 4.4 第四阶段：深度定制 (第3个月)

**目标**: 根据实际需求定制功能

**可选优化**:
1. 自定义AI模型（微调Whisper、YOLO）
2. 开发专用插件（特定领域识别）
3. 优化搜索算法（混合搜索、重排序）
4. 集成外部服务（Slack通知、API接口）
5. 性能监控仪表板

## 八、最终建议

### 8.1 适用性评估

✅ **强烈推荐** - 如果您：
- 有高性能GPU硬件（已满足）
- 需要处理大量视频内容
- 重视数据隐私和安全
- 有一定技术能力
- 预算有限，希望降低长期成本

⚠️ **谨慎评估** - 如果您：
- 视频数量极大（>10万）
- 需要企业级SLA保障
- 团队缺乏技术支持
- 对生产就绪度要求极高

❌ **不推荐** - 如果您：
- 没有GPU硬件
- 视频处理需求很少
- 更看重即开即用的便利性
- 预算充足，愿意支付API费用
